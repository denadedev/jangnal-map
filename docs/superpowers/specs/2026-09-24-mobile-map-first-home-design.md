# 모바일 홈 지도 우선 설계

**작성일:** 2026-09-24
**상태:** 2026-09-24 대화에서 방향 승인, 구현 계획 기준
**범위:** `apps/web` 홈의 700px 이하 레이아웃과 시장 선택 흐름

## 목적

이동 중인 사용자가 지도를 보며 가까운 장날 시장을 고르고, 핀을 누른 뒤에도 위치를 잃지 않은 채 다음 장날을 확인한다. 첫 화면과 핀 선택 상태에서 지도가 실제로 조작 가능해야 한다. 기존의 `평택 검색 → 시장 선택 → 다음 장날 확인` 10초 목표를 유지한다.

이 문서는 [2026-09-21 모바일 UX 설계](2026-09-21-mobile-ux-redesign-design.md)의 홈 화면 결정만 갱신한다. 그 문서의 앱 바, 검색, 시트 결정 중 홈에서 별도 앱 바를 두고 핀 선택 시 전체 상세를 즉시 여는 부분을 이 문서가 대체한다. 다른 경로, 데스크톱, 데이터·장날 계산·SEO URL은 기존 설계를 따른다.

## 홈 화면 구조

- 지도가 모바일 홈의 전체 가용 화면을 채운다. 검색과 날짜 선택은 지도 상단의 단일 플로팅 영역에, 결과 시트는 지도 하단에 겹친다. 플로팅 영역은 안전 영역과 지도 저작권 표시를 가리지 않는다.
- 상단 첫 줄은 작은 `장` 브랜드 표시, 16px 이상 입력 글자의 검색창, 44×44px 이상 메뉴 버튼이다. 브랜드 이름은 접근 가능한 이름으로도 제공한다. 독립된 59px 모바일 앱 바는 홈에서 렌더링하지 않는다. 하위 경로의 공통 앱 바는 그대로 둔다.
- 상단 둘째 줄은 `전체`, `오늘`, `이번 주`, `주말`, `날짜 선택`의 가로 스크롤 필터다. 현재 선택을 언제나 읽을 수 있고 버튼 기반 네이티브 날짜 선택은 유지한다. 날짜 직접 선택 시 입력을 위한 추가 줄은 필요할 때만 열린다.
- `시장별 방문 정보`는 결과 시트 안의 접을 수 있는 섹션으로 옮긴다. 홈 모바일의 고정 푸터는 없앤다. 푸터가 제공하던 `서비스 소개`, `개인정보 처리방침`, `이용약관`, `데이터 출처와 편집 기준`, `정보 수정 제보` 링크는 모바일 메뉴에서 모두 접근 가능해야 한다. 데스크톱 푸터는 유지한다.
- 지도가 없거나 SDK에 실패하면 플로팅 검색·필터와 전체 높이 목록을 유지하고 지도 전용 조작은 숨긴다.

## 시트와 선택 흐름

| 상태 | 진입 | 지도와 행동 |
| --- | --- | --- |
| 결과 접힘 | 지도 정상 진입, 상세 닫기 | 높이 60–70px. 결과 수와 `목록 열기`가 하나의 44px 이상 조작 영역에 보인다. |
| 결과 절반 | `목록 열기`, 결과 시트 위로 드래그 | 결과를 스크롤하면서 지도의 일부를 조작할 수 있다. |
| 결과 전체 | 명시적인 `목록 크게 보기`, 지도 실패, 데이터 오류·결과 없음 | 목록 또는 오류·초기화 행동에 집중한다. `지도 보기`로 돌아간다. |
| 시장 미리보기 | 지도 핀 선택 | 높이 150–180px. 시장명, 다음 장날 또는 운영 상태, 주소 한 줄, `상세 보기`, 닫기가 보인다. 배경 지도는 조작 가능하다. |
| 시장 전체 상세 | 목록 항목 선택, 미리보기의 `상세 보기`, 공유 URL 직접 진입 | 현재 `MarketDetail` 콘텐츠를 전체 시트로 보여준다. 지도 조작과 배경 포커스는 막는다. |

핀 선택과 목록 선택은 같은 `selectedId`를 사용한다. 미리보기에서 전체 상세로 전환할 때 브라우저 히스토리를 추가하지 않는다. `market` URL 파라미터는 두 선택 모두에 사용한다. 지도에서 연 미리보기 여부는 해당 히스토리 항목의 일시 상태에 저장한다. 직접 연 `?market=` URL은 전체 상세로 연다. 뒤로가기나 닫기는 선택 전 결과 시트 높이, 검색·날짜, 목록 스크롤, 지도 중심·줌을 복원한다. 필터 변경으로 선택 시장이 제외되면 선택을 해제한다.

좌표 없는 시장은 목록에서 전체 상세로 열 수 있지만 지도 미리보기와 길찾기는 제공하지 않는다. 목록 항목에는 핀 선택과 구분되는 명시적인 전체 상세 진입 동작을 유지한다.

## 지도 가시 영역

- 선택 시장은 지도 위쪽 컨트롤과 아래쪽 시트 사이의 **가리지 않은 직사각형** 안에 나타난다. 시트 높이와 상단 컨트롤 높이는 DOM에서 측정해 지도 뷰포트 패딩에 반영한다. 고정 픽셀 가정이나 시트 높이의 절반만큼 무조건 이동하는 방식에 의존하지 않는다.
- 위치 버튼은 시트 상단과 겹치지 않게 배치하고, 검색·날짜 컨트롤 및 지도 출처·NAVER 로고를 가리지 않는다. 결과 접힘·절반 또는 시장 미리보기처럼 지도를 조작할 수 있는 상태에서 출처와 로고가 보여야 한다. 전체 상세가 모달로 열리면 지도 조작 버튼을 숨긴다.
- 시트 크기 변경이나 화면 회전 시 패딩을 갱신한다. 사용자가 지도를 직접 움직인 뒤 시트만 변경하면 강제로 이전 중심으로 되돌리지 않는다. 새 시장 선택 또는 선택 핀이 가려진 경우에만 다시 맞춘다.
- 목표는 375×667 CSS 픽셀 화면의 첫 진입에서 **가리지 않은 조작 가능 지도 높이 60% 이상**, 그리고 핀 선택 시 선택 핀이 가리지 않은 영역 안에 남는 것이다. 320×568에서는 검색·결과 열기·지도 조작이 잘리지 않는 것을 우선한다.

NAVER Maps는 픽셀 단위 `padding` 옵션을 제공하며 지도 컨트롤과 저작권 표시는 지도 옵션으로 배치한다. 구현은 공식 [지도 옵션](https://navermaps.github.io/maps.js.en/docs/naver.maps.Map.html)과 [컨트롤 지침](https://navermaps.github.io/maps.js.ncp/docs/tutorial-Controls.html)을 따른다.

## 접근성과 예외

- 결과 시트의 접힌 바, 메뉴, 필터, 미리보기의 닫기·상세 보기는 최소 44×44px의 조작 영역을 제공한다. 별도의 작은 드래그 손잡이에만 상태 전환을 맡기지 않는다.
- 미리보기는 비모달 `region`, 전체 상세는 `dialog`로 취급한다. 미리보기에서 키보드 사용자는 지도와 필터를 계속 사용할 수 있다. 전체 상세를 닫으면 원래 목록 항목 또는 지도 핀으로 초점을 돌리고, 핀이 재생성됐다면 결과 열기 버튼으로 보낸다.
- 검색 키보드가 열리면 검색과 결과에 집중할 수 있게 목록을 펼치고, 키보드를 닫거나 시장을 고르면 지도 맥락으로 돌아온다. `visualViewport` 변화, iOS 안전 영역, 200% 텍스트 확대에서도 행동이 가려지지 않는다.
- `prefers-reduced-motion` 설정을 존중한다. 지도 실패, 로딩·데이터 오류, 결과 없음, 위치 권한 거부는 기존 탐색 대체 경로를 유지한다.

## 검증 기준

- 320×568, 375×667, 375×844, 430×844에서 가로 넘침과 핵심 조작 잘림이 없다.
- 지도 정상 상태에서 핀 선택은 미리보기로, 목록 선택과 직접 공유 URL은 전체 상세로 열린다. 상세 닫기·브라우저 뒤로가기·앞으로가기가 URL과 시트 상태를 일치시킨다.
- 실제 NAVER 지도의 결과 접힘·절반·시장 미리보기 상태에서 선택 핀과 로고·저작권 표시가 시트와 상단 컨트롤에 가리지 않는다. 지도 키가 없는 자동 검증만으로 이 항목을 완료 처리하지 않는다.
- `pnpm test`, `pnpm typecheck`, `pnpm build`, 모바일 Playwright가 통과한다. iPhone Safari와 Android Chrome 실기기에서 시트 드래그, 키보드, 안전 영역, 지도 조작을 기록한다.

# 모바일 UX 재설계

**작성일:** 2026-09-21  
**상태:** 승인된 설계  
**대상:** `apps/web`의 모든 공개 모바일 화면

## 1. 목표

이 작업의 목표는 이동 중인 사용자가 모바일에서 검색, 날짜 필터, 지도, 시장 목록과 상세정보를 자연스럽게 오가며 10초 안에 방문할 시장의 다음 장날을 확인하도록 만드는 것이다.

기능 추가보다 모바일 정보 구조와 조작 흐름을 우선한다. 기존 데이터 모델, 장날 계산, 공개 URL, 브랜드 색상과 콘텐츠는 유지한다. 성능은 사용자의 입력이나 화면 전환을 방해하는 문제만 이번 범위에서 함께 개선한다.

## 2. 범위

다음 공개 화면과 공통 UI를 포함한다.

- 홈 시장 탐색기: 검색, 날짜 필터, 지도, 시장 목록과 시장 상세 시트
- 시장 상세 경로: `/markets/[slug]`
- 온누리상품권 안내: `/onnuri`
- 시장 정보 수정 및 서비스 불편 제보: `/report`
- 개인정보 처리 안내: `/privacy`
- 공통 앱 바, 보조 메뉴와 홈 화면 설치 동작

다음 항목은 제외한다.

- 장날 계산 규칙, 시장 데이터와 API 계약 변경
- 새로운 사용자 계정, 즐겨찾기 또는 알림 기능
- 데스크톱 정보 구조의 전면 재설계
- 네이티브 모바일 앱
- 별도 성능 최적화 프로젝트

## 3. 사용 환경과 성공 기준

주 사용 환경은 360–430px 너비의 iPhone Safari와 Android Chrome이다. 320px부터 가로 스크롤이나 콘텐츠 잘림 없이 핵심 작업을 완료할 수 있어야 하며, 700px 이하를 모바일 레이아웃으로 취급한다.

다음 조건을 충족해야 한다.

- 첫 화면 진입 후 3초 안에 검색 또는 날짜 탐색을 시작할 수 있다.
- `평택 검색 → 시장 선택 → 다음 장날 확인` 대표 과제를 10초 안에 완료한다.
- 다음 장날과 길찾기 행동이 상세 첫 화면 또는 한 번의 세로 스크롤 안에 있다.
- 상세 진입과 복귀 뒤에도 검색어, 날짜 조건, 지도 위치와 목록 스크롤이 유지된다.
- 320, 360, 375, 390, 430px 너비에서 가로 스크롤과 콘텐츠 잘림이 없다.
- 주요 터치 대상은 최소 44×44px이고 폼 입력 글자는 최소 16px이다.

## 4. 핵심 설계 결정

### 4.1 지도와 스냅 시트를 결합한 홈

모바일 홈은 지도와 목록을 세로로 이어 붙인 현재 구조 대신 하나의 화면 높이 안에서 동작한다. 상단에는 컴팩트 앱 바, 검색과 날짜 필터를 두고 지도는 남은 공간을 차지한다. 결과 목록은 지도 위의 스냅 시트로 표시한다.

시트는 세 단계로 동작한다.

1. **접힘:** 기본 상태다. 시트 제목과 `목록 열기` 버튼만 보여 지도 탐색 공간을 확보한다.
2. **절반:** 지도와 여러 결과를 함께 비교한다.
3. **전체:** 검색 결과 목록 또는 시장 상세정보에 집중한다.

모바일 첫 화면의 시장별 방문 정보도 접힌 상태로 시작한다.

드래그 손잡이와 함께 `목록 열기`, `목록 크게 보기`, `지도 보기` 버튼을 제공한다. 모든 상태 전환은 버튼만으로도 가능해야 하며 드래그 제스처에 의존하지 않는다.

### 4.2 결과와 상세의 단일 시트 흐름

지도 핀 또는 목록 항목을 선택하면 같은 시트가 결과 목록에서 시장 상세정보로 전환된다. 상세 화면에서 닫기 또는 브라우저 뒤로가기를 실행하면 상세 이전의 결과 목록과 시트 높이로 돌아간다.

상태 계층은 다음과 같다.

```text
홈 탐색
  ├─ 결과 시트: 접힘 / 절반 / 전체
  └─ 시장 상세 시트
       └─ 닫기 또는 뒤로가기 → 이전 결과 시트 상태
```

시장 상세를 닫아도 검색어, 날짜 필터, 직접 선택 날짜, 지도 중심·확대 수준, 현재 위치, 목록 스크롤 위치를 보존한다.

### 4.3 공통 앱 바와 보조 메뉴

모든 화면은 같은 모바일 앱 바 규칙을 사용한다.

- 홈: 브랜드와 보조 메뉴 버튼
- 하위 화면: 뒤로가기, 화면 제목과 홈 이동
- 보조 메뉴: 온누리상품권, 불편 신고, 개인정보 처리 안내

핵심 작업이 시장 탐색 하나이므로 상시 하단 탭은 추가하지 않는다. 지도 공간을 보존하고 보조 기능은 앱 바 메뉴에서 제공한다.

현재의 큰 설치 배너는 제거한다. 설치 가능한 브라우저에서만 보조 메뉴에 `홈 화면에 추가`를 표시한다. iOS에서는 선택 시 설치 절차를 안내하고, 네이티브 설치 이벤트를 제공하는 브라우저에서는 해당 이벤트를 실행한다.

## 5. 홈 탐색 상세 설계

### 5.1 검색과 날짜 필터

- 검색 입력은 앱 바 아래 첫 번째 조작 요소로 유지한다.
- 날짜 필터는 한 줄 가로 스크롤 영역으로 제공하며 선택 상태와 양쪽 잘림 힌트를 함께 보여준다.
- 직접 날짜는 별도 줄에 상시 노출하지 않고 `날짜` 버튼으로 네이티브 날짜 선택기를 연다.
- 검색어나 날짜 조건이 바뀌어 선택 시장이 제외되면 상세를 닫고 새 결과 시트를 접힘 상태로 표시한다.
- 검색 결과가 없으면 시트를 전체 상태로 열고 조건 초기화 행동을 제공한다.

### 5.2 지도와 목록 동기화

- 지도 핀과 목록 선택은 하나의 `selectedId` 상태를 공유한다.
- 시장을 선택하면 지도를 이동해 선택 핀이 시트에 가리지 않는 영역에 들어오게 한다.
- 지도 이동이나 확대·축소 후에도 활성 검색과 날짜 조건은 유지한다.
- 현재 위치를 받으면 목록을 거리순으로 정렬한다.
- 위치 권한 거부 또는 위치 확인 실패 시 지역 검색으로 이동하는 행동을 제공하고 검색 입력에 초점을 둔다.

### 5.3 지도 실패와 데이터 오류

- 지도 키가 없거나 SDK가 실패하면 지도를 숨기고 결과 시트를 전체 높이 목록으로 전환한다.
- 시장 데이터 로딩 실패는 전체 시트의 오류 상태로 표시하고 `다시 시도`를 제공한다.
- 좌표가 없는 시장은 목록과 상세에서 계속 사용할 수 있으며 길찾기 대신 위치 확인 필요 상태를 보여준다.
- 지도 실패가 목록 검색, 날짜 필터, 상세 열기를 막지 않아야 한다.

## 6. 시장 상세 설계

상세 시트와 독립 시장 상세 페이지는 동일한 콘텐츠 우선순위를 사용한다.

1. 시장명, 시장 유형과 주소
2. 다음 장날 또는 운영 일정과 D-day
3. 가까운 장날 일정
4. 주소, 전화와 주차 등 방문 정보
5. 길찾기와 공유
6. 온누리상품권 정보
7. 출처, 기준일과 수정 제보

길찾기는 가장 높은 강조도의 행동으로 제공한다. 모바일 독립 상세 페이지에서는 화면 하단 안전 영역 위에 고정하되 본문 마지막 콘텐츠를 가리지 않도록 여백을 확보한다. 공유와 수정 제보는 보조 행동으로 구분한다.

상세 시트는 열린 직후 제목으로 포커스를 이동하지 않는다. 시트를 연 조작 요소와 문맥을 유지하되 화면 읽기 도구에는 `aria-live`로 선택 시장을 알린다. 시트 내부를 키보드로 순환할 수 있고 닫으면 선택했던 핀 또는 목록 항목으로 포커스를 돌려준다.

## 7. 보조 화면 설계

### 7.1 온누리상품권

- 페이지 제목 다음에 핵심 설명과 공식 가맹점 찾기 행동을 먼저 배치한다.
- 디지털형과 지류형의 차이, 방문 전 확인 주의사항은 한 열 카드로 표시한다.
- 시장 상세 안의 온누리 요약은 숫자, 기준일, 공식 확인 링크 순서를 유지한다.

### 7.2 제보

- 모바일에서는 외곽 카드 장식을 제거하고 화면 폭을 입력에 사용한다.
- 라디오 선택지는 한 열로 유지하며 전체 행을 터치 영역으로 사용한다.
- 모든 텍스트 입력은 16px 이상으로 설정해 iOS 자동 확대를 막는다.
- 검증 실패 시 첫 오류 필드로 초점과 화면을 이동한다.
- 가상 키보드가 열렸을 때 입력, 오류 문구와 제출 버튼이 가려지지 않아야 한다.
- 제출 중, 성공, 서버 실패와 요청 제한 상태는 현재 입력값을 보존하면서 명확히 안내한다.

### 7.3 개인정보 처리 안내

- 모바일에서는 카드 컨테이너를 제거해 본문 읽기 폭을 확보한다.
- 제목, 절 제목, 본문과 링크 사이의 간격 체계를 문서 전체에 일관되게 적용한다.
- 긴 이메일 주소와 외부 링크가 줄바꿈돼 화면을 넘지 않게 한다.

## 8. 상태와 URL

다음 탐색 상태를 URL 쿼리에 유지한다.

- 검색어: `q`
- 날짜 모드: `when`
- 직접 날짜: `date`
- 선택 시장: `market`

시트 높이, 지도 중심·확대 수준과 목록 스크롤 위치는 브라우저 세션의 일시 상태로 관리하고 공유 URL에는 넣지 않는다. 브라우저 뒤로가기는 상세 선택처럼 사용자에게 의미 있는 상태 변화만 되돌린다. 시트 높이만 바꾸는 동작은 히스토리를 추가하지 않는다.

새로고침이나 공유 URL 진입 시 URL 상태를 먼저 복원하고, 선택 시장이 현재 조건에 없으면 선택을 해제한 뒤 결과 상태를 보여준다.

## 9. 접근성과 동작

- 모든 주요 터치 대상은 최소 44×44px이다.
- 검색, 날짜 선택, 시장 선택, 시트 전환, 상세 닫기와 제보 제출을 키보드로 수행할 수 있다.
- 앱 바 메뉴는 열릴 때 첫 항목으로 포커스를 이동하고 닫히면 메뉴 버튼으로 돌려준다.
- 메뉴와 전체 상세 시트가 열린 동안 배경 스크롤과 배경 포커스를 막는다.
- 시트의 현재 상태와 선택 시장은 이름이 있는 버튼 및 상태 문구로 전달한다.
- `prefers-reduced-motion`에서는 시트와 메뉴 전환 시간을 사실상 제거한다.
- `env(safe-area-inset-top)`과 `env(safe-area-inset-bottom)`을 앱 바, 시트와 고정 행동에 반영한다.
- 200% 확대와 큰 글자에서 내용이나 행동이 잘리지 않아야 한다.

## 10. 검증 전략

### 10.1 컴포넌트 테스트

기존 Vitest와 Testing Library 테스트에 다음 동작을 추가한다.

- 결과 시트 세 상태와 버튼 기반 상태 전환
- 핀·목록·상세 선택 동기화와 닫은 뒤 상태 복원
- URL 상태 복원과 유효하지 않은 시장 선택 제거
- 지도 키 없음, 지도 실패, 데이터 실패와 결과 없음 상태
- 위치 권한 거부 후 지역 검색 초점 이동
- 메뉴 포커스 복원과 조건부 설치 행동
- 제보 검증 실패 시 첫 오류 필드 이동과 입력값 보존

### 10.2 모바일 브라우저 테스트

Playwright를 개발 의존성으로 추가하고 다음 경로를 모바일 뷰포트에서 검증한다.

- 홈: 검색, 날짜 필터, 결과 시트, 시장 선택과 뒤로가기
- 독립 시장 상세: 장날 확인, 길찾기, 공유와 제보 이동
- 온누리상품권: 핵심 정보와 공식 링크
- 제보: 입력, 검증, 실패와 성공 상태
- 개인정보: 긴 콘텐츠와 링크 줄바꿈

320, 375, 390, 430px의 대표 뷰포트에서 가로 오버플로우 검사와 스크린숏 회귀 검사를 실행한다. 프로덕션 빌드를 대상으로 브라우저 콘솔 오류와 실패한 정적 자산 요청도 확인한다.

### 10.3 실기기 검증

iPhone Safari와 Android Chrome에서 다음을 수동 확인한다.

- 시트 드래그와 버튼 전환
- 브라우저 뒤로가기
- 네이티브 날짜 선택기
- 가상 키보드와 폼 오류 이동
- 안전 영역과 가로 회전
- 위치 권한 허용·거부
- 외부 지도 길찾기와 홈 화면 설치

5명 내외의 짧은 과업 테스트에서 `평택 검색 → 시장 선택 → 다음 장날 확인` 완료 시간과 막힌 지점을 기록한다. 10초 목표를 충족하지 못한 주요 흐름은 배포 전에 수정한다.

## 11. 완료 조건

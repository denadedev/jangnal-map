# 시장별 SEO 페이지 설계

## 목적

현재 서비스는 모든 시장 상세정보를 메인 지도 페이지의 쿼리 문자열과 바텀시트로 제공한다. 검색엔진이 시장별 콘텐츠를 독립된 문서로 이해하기 어려워 `용인중앙시장 장날`, `제천 전통시장` 같은 구체적인 검색어에 대응하기 어렵다.

운영 중인 1,393개 시장에 공유 가능한 고유 주소와 완성된 HTML 상세 페이지를 제공한다. 기존 지도 탐색 경험은 유지하며, 검색 결과로 들어온 사용자가 해당 시장 정보를 확인하고 선택된 지도 화면으로 이동할 수 있게 한다.

## 접근 방식

Next.js 빌드 시 시장별 정적 페이지를 생성한다. 현재 시장 데이터가 정적 JSON으로 배포되고 이후 갱신도 배포 단위로 이루어지므로, 요청마다 서버에서 페이지를 생성하는 방식보다 구조가 단순하고 응답이 빠르다.

쿼리 문자열만 검색엔진에 노출하는 방식은 시장별 canonical URL과 HTML을 안정적으로 제공하기 어려워 사용하지 않는다. 동적 서버 렌더링은 데이터가 실시간으로 변경되는 백엔드 단계까지 보류한다.

## URL 규칙

시장 주소는 `/markets/{시장명-slug}-{ID-접미사}` 형식을 사용한다.

예시:

```text
/markets/용인중앙시장-389b4a24
```

- 시장명은 사용자가 읽을 수 있는 URL 문자로 정규화한다.
- 공백과 URL에 부적합한 문자는 하이픈으로 치환한다.
- 기존 결정적 시장 ID의 접미사를 붙여 같은 이름의 시장을 구분한다.
- 생성된 전체 slug를 데이터에서 조회하므로 시장명 안의 하이픈과 ID 경계를 추측해 파싱하지 않는다.
- 페이지의 canonical URL은 배포 도메인 `https://jangnal-map.vercel.app`을 기준으로 지정한다.
- 존재하지 않는 slug는 404로 처리한다.

## 페이지 범위와 색인 정책

운영 중인 공개 시장 1,393곳 모두 상세 페이지를 생성한다.

| 일정 유형 | 페이지 생성 | 검색 색인 | 핵심 표현 |
|---|---:|---:|---|
| 정기 장날 | 예 | 허용 | 다음 장날, `4·9일장` 같은 일정 |
| 매일 운영 | 예 | 허용 | 매일 운영, 주소와 방문 정보 |
| 일정 미확인 | 예 | 제외 | 운영 일정 확인 필요 |

일정 미확인 시장 2곳은 사용자가 링크로 접근할 수 있지만 `robots` 메타데이터를 `noindex`로 설정하고 사이트맵에서 제외한다. 폐장 상태 데이터가 추가되면 페이지를 생성하지 않고 사이트맵에서도 제외한다.

## 상세 페이지 콘텐츠

페이지는 서버 컴포넌트로 렌더링하고 다음 정보를 제공한다.

- 서비스 브랜드와 메인 지도 링크
- 시장명과 시장 유형
- 정기 장날 패턴 또는 매일 운영 상태
- 브라우저의 오늘 날짜를 기준으로 계산한 다음 장날
- 도로명 또는 지번 주소
- 전화번호와 주차 가능 여부
- 좌표가 있을 때 NAVER 지도 길찾기 링크
- 해당 시장이 선택된 메인 지도로 이동하는 버튼
- 데이터 기준일과 간결한 출처 안내

검색 유입 사용자가 모바일에서도 한 화면에서 핵심 정보를 먼저 볼 수 있도록 시장명, 일정, 다음 장날, 주소 순으로 배치한다. 기존 바텀시트를 그대로 재사용하지 않고 검색 결과 진입에 적합한 독립 페이지 레이아웃을 사용한다.

## 메타데이터

일정 유형에 따라 제목과 설명을 다르게 만든다.

- 정기 장날 제목: `{시장명} 장날 · {일정} | 오늘 장날`
- 매일 운영 제목: `{시장명} 영업일 · 매일 운영 | 오늘 장날`
- 일정 미확인 제목: `{시장명} 전통시장 정보 | 오늘 장날`

설명에는 시장명, 지역과 변하지 않는 장날 패턴을 사실에 맞게 포함한다. 정적 HTML과 메타데이터에는 배포 다음 날부터 오래될 수 있는 정확한 다음 장날 날짜를 넣지 않는다. 데이터에 없는 지역명이나 운영시간을 추측하지 않는다. 모든 색인 가능 페이지에 canonical URL과 Open Graph 기본 정보를 제공한다.

정확한 다음 장날은 작은 클라이언트 컴포넌트가 브라우저의 오늘 날짜를 기준으로 계산한다. 정적 HTML에는 `5·10일장`처럼 변하지 않는 일정이 남으므로 JavaScript 실행 전에도 검색엔진과 사용자에게 정확한 정보를 제공한다.

## 구조화 데이터

색인 가능한 상세 페이지에 JSON-LD `Place` 데이터를 제공한다.

- `name`
- `url`
- `address`
- 좌표가 있는 경우 `geo`
- 전화번호가 있는 경우 `telephone`

정기 장날을 Schema.org의 매주 영업시간으로 잘못 표현하지 않는다. 장날 정보는 페이지 설명과 본문에만 정확히 제공한다.

## 사이트맵과 검색 정책

- `sitemap.xml`에는 색인 가능한 운영 시장 페이지만 포함한다.
- 각 항목의 URL은 canonical URL과 일치해야 한다.
- 데이터 기준일이 있으면 `lastModified`로 사용하고 없으면 임의 날짜를 생성하지 않는다.
- `robots.txt`는 일반 검색엔진의 공개 페이지 접근을 허용하고 사이트맵 주소를 알린다.
- 루트 페이지의 기본 메타데이터도 서비스명과 전국 장날 탐색 목적을 구체적으로 표현한다.

## 데이터 흐름과 모듈 경계

SEO 전용 라이브러리가 공개 JSON을 읽어 다음 기능을 제공한다.

1. 시장별 안정적인 slug 생성
2. slug로 시장 조회
3. 시장별 제목과 설명 생성
4. canonical URL 생성
5. 색인 가능 여부 판단

상세 페이지, 메타데이터, 사이트맵이 이 라이브러리를 함께 사용해 URL이나 색인 규칙이 서로 달라지지 않게 한다. 기존 지도 필터와 장날 계산 함수는 재사용하고 데이터베이스나 API는 추가하지 않는다.

## 오류 처리

- 알 수 없는 slug는 Next.js 404 페이지를 반환한다.
- 주소, 전화, 주차 또는 좌표가 없으면 해당 항목을 사실에 맞는 안내로 표시하거나 생략한다.
- 다음 장날을 계산할 수 없는 일정은 임의 날짜를 표시하지 않는다.
- SEO 페이지 오류가 메인 지도 탐색 기능에 영향을 주지 않도록 라우트를 분리한다.

## 검증 기준

- 서로 다른 1,393개 slug가 생성되고 중복이 없다.
- 같은 이름의 시장도 서로 다른 URL을 갖는다.
- 정기 장날, 매일 운영, 일정 미확인 시장의 제목과 설명이 각 규칙에 맞는다.
- 일정 미확인 시장은 `noindex`이며 사이트맵에 포함되지 않는다.
- 존재하지 않는 slug가 404를 반환한다.
- 정기 장날 페이지의 정적 HTML과 SEO 메타데이터에는 변하지 않는 일정 패턴이 표시된다.
- 브라우저가 실행되면 오늘 날짜를 기준으로 다음 장날이 정확히 표시된다.
- 상세 페이지의 지도 이동 버튼이 기존 `market` 쿼리와 연결된다.
- `sitemap.xml`과 `robots.txt`가 운영 도메인의 올바른 URL을 제공한다.
- 1,393개 상세 페이지를 포함한 프로덕션 빌드가 성공한다.
- 375px 모바일과 데스크톱에서 핵심 정보와 이동 버튼을 사용할 수 있다.
- 기존 지도, 검색, 필터, 현재 위치와 상세 바텀시트에 회귀가 없다.

## 배포

SEO 작업은 독립 브랜치와 PR로 배포한다. 로컬 테스트, 타입 검사, 전체 정적 빌드, 대표 페이지 시각 검증 후 PR CI를 통과시킨다. `main` 병합으로 Vercel Production 배포를 시작하고 운영 도메인에서 대표 시장 페이지, 메타데이터, 사이트맵, robots 파일과 404를 다시 검증한다.

## 제외 범위

- 검색 순위 보장
- 네이버 서치어드바이저와 Google Search Console 계정 등록
- 광고 코드 및 수익화 기능
- 데이터베이스와 백엔드 API
- 시장 후기, 게시글 또는 사용자 생성 콘텐츠
- 지역별 목록 랜딩 페이지

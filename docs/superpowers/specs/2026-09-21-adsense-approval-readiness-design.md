# AdSense 승인 준비 설계

## 목표

`spamfam.kr`을 Google AdSense 정책에 맞는 승인 후보로 만든다. 승인 전에는 광고 요청을 전혀 만들지 않고, 사이트 소유권은 AdSense 메타 태그와 `ads.txt`로 증명한다. 검색 색인과 향후 광고 대상은 편집 검수를 통과한 콘텐츠로 제한한다.

## 배경과 확인된 문제

AdSense는 사이트를 "게시자 콘텐츠가 없는 화면의 Google 게재 광고" 정책 위반으로 거절했다. 운영 환경 확인 결과 전역 레이아웃의 AdSense 스크립트가 홈, 제보, 개인정보, 시장 상세, 404를 포함한 모든 화면에서 실행되고 `adsbygoogle` iframe을 생성했다.

사이트에는 다음 문제도 있다.

- 실제 서비스와 AdSense 신청 주소는 `https://spamfam.kr`이지만 canonical, sitemap, robots, 분석 도메인은 `https://jangnal.spamfam.kr`을 가리킨다.
- 1,391개 시장 상세가 색인 대상이지만 대부분 같은 템플릿과 공공데이터 필드로 구성된다.
- 개인정보 처리방침은 존재하지만 데스크톱 홈에서 찾기 어렵다.
- 서비스 운영 주체, 편집 기준, 데이터 책임을 설명하는 소개 페이지와 공통 신뢰 푸터가 없다.

## 성공 기준

1. 승인 요청 시점에 어떤 페이지도 `adsbygoogle.js`, `ins.adsbygoogle`, Google 광고 iframe을 생성하지 않는다.
2. 모든 페이지의 AdSense 소유권 메타 태그는 `ca-pub-3237088758901901`을 사용한다.
3. `https://spamfam.kr/ads.txt`가 HTTP 200과 정확히 다음 한 줄을 반환한다.

   ```text
   google.com, pub-3237088758901901, DIRECT, f08c47fec0942fa0
   ```

4. canonical, Open Graph URL, sitemap, robots host, 분석 도메인, 레거시 호스트 리디렉션이 `https://spamfam.kr`로 일치한다.
5. 홈, 소개, 개인정보, 데이터 출처, 제보 화면을 사용자가 공통 푸터에서 찾을 수 있다.
6. 사이트맵에는 홈, 소개, 편집 완료된 온누리 안내, 편집 검수를 통과한 시장 30곳만 포함된다.
7. 미검수 시장 페이지는 서비스에서 접근 가능하지만 `noindex, follow`이고 광고 대상이 아니며 사이트맵에 포함되지 않는다.
8. 검수 시장 30곳은 동일 템플릿을 반복하지 않고, 출처와 확인일이 있는 시장별 고유 정보를 제공한다.
9. 배포 후 대표 URL과 404에서 광고 요청 부재, 메타 태그, canonical, robots, sitemap, `ads.txt`를 실제 운영 환경에서 검증한다.

## 범위

### 포함

- AdSense 전역 광고 스크립트 제거
- AdSense 소유권 메타 태그와 `ads.txt` 적용
- 승인 후 광고를 검수 콘텐츠에만 명시적으로 허용할 수 있는 구조
- canonical 도메인 통일과 레거시 호스트 리디렉션
- 공통 신뢰 푸터, 서비스 소개, 데이터 출처 설명
- 검수 상태를 포함한 시장 편집 콘텐츠 모델
- 초기 검수 시장 30곳 선정과 콘텐츠 작성
- 사이트맵과 `noindex` 규칙 변경
- 온누리 안내 페이지 보강
- 자동 테스트와 운영 환경 검증

### 제외

- 승인 전에 실제 광고 단위를 배치하는 작업
- 1,393개 시장 전체의 편집 콘텐츠 작성
- 현장 방문을 하지 않고 운영시간, 대표 품목, 주차 요금 등 확인되지 않은 사실을 추정하는 작업
- 승인 결과를 보장하거나 Google 검토 시점을 예측하는 작업
- 지도 검색, 날짜 필터, 제보 기능의 제품 동작 변경

## 승인 준비 아키텍처

### 1. 소유권 확인과 광고 실행 분리

루트 레이아웃은 다음 메타 태그만 전역으로 렌더링한다.

```html
<meta name="google-adsense-account" content="ca-pub-3237088758901901">
```

전역 `adsbygoogle.js` 스크립트는 제거한다. 승인 전에는 어떤 경로도 광고 스크립트를 렌더링하지 않는다. 소유권은 메타 태그와 루트의 `ads.txt`로 확인한다.

승인 후 광고를 다시 도입할 때도 루트 레이아웃에 스크립트를 되돌리지 않는다. 검수된 시장 상세처럼 광고 허용 조건을 충족하는 서버 렌더링 경로에서만 전용 컴포넌트를 명시적으로 렌더링한다. 홈 지도, 검색·필터 결과, 제보, 개인정보, 소개, 오류, 미검수 시장은 영구적인 광고 제외 화면이다.

### 2. 단일 canonical 도메인

공식 사이트 주소는 `https://spamfam.kr`이다. `SITE_URL`, `metadataBase`, sitemap, robots, JSON-LD, Open Graph URL, Umami `data-domains`를 이 값으로 통일한다.

`jangnal-map.vercel.app`과 `jangnal.spamfam.kr` 요청은 경로와 쿼리 문자열을 보존한 채 `https://spamfam.kr`로 영구 리디렉션한다. 동일 콘텐츠가 여러 호스트에서 200으로 제공되지 않게 한다.

### 3. 검수 상태와 색인 정책

시장 원본 데이터와 편집 콘텐츠를 분리한다.

- `markets.json`: 장날, 주소, 좌표, 전화, 주차, 온누리 집계 등 서비스 원본 데이터
- `market-editorial.json`: 운영자가 검수한 시장별 고유 콘텐츠와 출처

편집 레코드는 최소한 다음 필드를 가진다.

```ts
interface MarketEditorialContent {
  marketId: string;
  summary: string;
  visitTips: string[];
  transportation: string;
  parking: string;
  specialties: string[];
  nearbyMarketIds: string[];
  sources: Array<{
    name: string;
    url: string;
    checkedAt: string;
  }>;
  reviewedAt: string;
  status: "reviewed";
}
```

`status: "reviewed"`인 편집 레코드가 있고 기본 일정이 확인된 시장만 색인할 수 있다. 편집 레코드가 없거나 필수 정보가 비어 있으면 시장 상세는 `noindex, follow`로 제공하고 사이트맵에서 제외한다.

색인 가능 여부와 광고 가능 여부는 별도 개념으로 유지한다. 승인 전 광고 가능 시장은 0곳이다. 승인 후에도 편집 검수 상태만으로 자동 광고를 켜지 않고, 별도의 운영 설정이 있어야 광고를 요청하도록 한다.

### 4. 초기 검수 시장 30곳

30곳은 다음 순서로 선정한다.

1. 운영 일정이 확인되고 주소와 좌표가 있는 시장
2. 공식 지방자치단체, 공공데이터, 시장 공식 채널 등 확인 가능한 출처가 있는 시장
3. 온누리상품권 집계 또는 방문 판단에 도움이 되는 추가 정보가 있는 시장
4. 한 지역에 편중되지 않도록 권역을 분산할 수 있는 시장
5. 동일 이름 시장처럼 사용자의 혼동을 해소할 필요가 있는 시장

검색량은 검증 가능한 데이터가 없으면 선정 근거로 사용하지 않는다. 각 페이지의 문장은 시장마다 새로 작성하고, 다른 시장에 그대로 복사할 수 있는 일반 문구는 고유 콘텐츠로 인정하지 않는다.

현장 확인이 필요한 사실은 작성하지 않는다. 주차 요금, 운영시간, 대표 품목처럼 변경 가능성이 높은 정보는 공식 출처가 있을 때만 표시하고 출처 확인일을 함께 기록한다. 확인할 수 없으면 "확인 필요"로 명시하되 검수 페이지의 핵심 가치로 계산하지 않는다.

### 5. 검수 시장 상세 구성

검수 시장 상세는 기존 장날, 다음 장날, 주소, 전화, 주차, 온누리 정보에 다음 편집 섹션을 추가한다.

- 한눈에 보는 시장 특징
- 방문 전에 알아둘 점
- 대중교통과 주차 안내
- 대표 품목 또는 시장 특성
- 함께 둘러볼 인근 시장
- 편집 출처와 최종 확인일

글자 수를 승인 기준으로 사용하지 않는다. 대신 모든 필수 섹션이 실제 시장 정보로 채워지고, 출처가 있으며, 중복 문구가 없는지를 품질 기준으로 사용한다.

### 6. 홈과 신뢰 페이지

홈 지도는 유용한 탐색 도구로 유지하지만 광고 대상에서는 제외한다. 홈에 "검수된 장날 방문 가이드" 영역을 추가해 30개 검수 시장으로 연결한다.

공통 푸터는 홈, 시장 상세, 온누리 안내, 소개, 개인정보 페이지에 표시한다. 푸터에는 다음 링크를 제공한다.

- 서비스 소개 (`/about`)
- 개인정보 처리방침 (`/privacy`)
- 데이터 출처와 편집 기준 (`/about#data-policy`)
- 정보 수정 제보 (`/report?kind=service`)

`/about`은 서비스 목적, 운영 주체 표시 방법, 데이터 출처, 갱신 방식, 편집 원칙, 오류 제보 절차를 설명한다. 저장소나 배포 설정에 확인 가능한 운영자 이름 또는 사업자 정보가 없다면 임의로 만들지 않고 서비스 운영 주체를 "오늘 장날 운영자"로 표시한다.

개인정보 처리방침에는 기존 AdSense 데이터 처리 안내를 유지하고 Google 파트너 사이트 데이터 사용 안내 링크를 추가한다. 개인정보, 소개, 제보 화면은 광고 제외 대상이다.

### 7. 온누리 안내 페이지

`/onnuri`는 현재 짧은 소개에서 다음 내용을 갖춘 안내 허브로 보강한다.

- 온누리상품권의 용도와 사용 조건
- 디지털형과 지류형 집계 해석 방법
- 가맹 여부가 변경될 수 있다는 안내
- 공식 가맹점 찾기 링크
- 데이터 출처, 집계 기준일, 갱신 방식
- 검수 시장 중 온누리 정보가 있는 시장 링크

보강과 출처 검수가 완료되면 색인하고 사이트맵에 포함한다. 완료 전에는 `noindex`와 사이트맵 제외를 적용한다.

## 오류와 예외 처리

- 존재하지 않는 시장 slug는 기존 404 처리를 유지하며 광고 스크립트를 렌더링하지 않는다.
- 잘못 인코딩된 slug는 예외 없이 404로 처리한다.
- 편집 레코드가 원본 시장 ID와 연결되지 않으면 빌드 또는 테스트에서 실패시킨다.
- 편집 레코드의 출처 URL, 확인일, 필수 텍스트가 없으면 검수 상태로 인정하지 않는다.
- 미검수 시장은 목록과 지도에서 계속 선택할 수 있지만 검색 엔진에는 `noindex, follow`를 보낸다.
- 광고 운영 설정이 빠지거나 꺼져 있으면 광고를 렌더링하지 않는 쪽으로 실패한다.

## 테스트 전략

### 단위 및 렌더링 테스트

- 루트 HTML에 AdSense 소유권 메타 태그가 있고 `adsbygoogle.js`가 없는지 검사
- `ads.txt`의 정확한 한 줄과 줄바꿈 검사
- canonical 관련 모든 상수가 `https://spamfam.kr`인지 검사
- 레거시 호스트 두 개의 영구 리디렉션 검사
- 검수 시장과 미검수 시장의 metadata robots 차이 검사
- 사이트맵이 검수 시장만 포함하는지 검사
- 편집 레코드 무결성, 출처 URL, ISO 날짜, 원본 시장 연결 검사
- 공통 푸터 링크가 주요 페이지에 보이는지 검사
- 개인정보 페이지의 Google 데이터 사용 안내 링크 검사
- 검수 시장 상세의 편집 섹션과 출처 표시 검사
- 온누리 페이지의 보강 콘텐츠와 출처 표시 검사

### 운영 환경 검증

배포 후 다음 URL을 실제 브라우저에서 확인한다.

- `/`
- 검수 시장 상세 1곳
- 미검수 시장 상세 1곳
- `/onnuri`
- `/about`
- `/privacy`
- `/report?kind=service`
- 존재하지 않는 URL
- `/robots.txt`
- `/sitemap.xml`
- `/ads.txt`

HTML과 네트워크에서 `pagead2.googlesyndication.com/pagead/js/adsbygoogle.js`, `ins.adsbygoogle`, Google 광고 iframe이 없는지 확인한다. 모든 HTML 문서에서 AdSense 계정 메타 태그를 확인하고 canonical이 `spamfam.kr`인지 검사한다. `ads.txt`, robots, sitemap은 HTTP 200과 예상 본문을 확인한다.

## 배포와 재검토 절차

1. 광고·도메인·신뢰 페이지 변경을 먼저 배포한다.
2. 검수 콘텐츠 30곳과 온누리 안내 보강을 배포한다.
3. Search Console에 새 sitemap을 제출하고 canonical 및 대표 URL 색인 상태를 확인한다.
4. AdSense 사이트 화면에서 소유권 확인 방식이 메타 태그 또는 `ads.txt`로 유지되는지 확인한다.
5. AdSense 자동 광고가 꺼져 있는지 확인한다.
6. 운영 환경 검증 체크리스트를 모두 통과한 뒤에만 "문제를 수정했음을 확인합니다"를 선택하고 재검토를 요청한다.
7. 재검토 중에는 광고 스크립트, 색인 정책, 콘텐츠 집합을 변경하지 않는다.

Google의 검토 결과와 처리 기간은 통제할 수 없다. 재검토가 거절되면 새 사유를 기준으로 다시 조사하며, 같은 코드 변경을 반복 제출하지 않는다.

## 위험과 대응

### 검색 색인 감소

사이트맵이 약 1,393개 URL에서 검수 콘텐츠 중심으로 줄어든다. 승인 우선 전략에서 의도한 결과다. 시장 데이터 탐색 기능은 유지하며, 편집 검수가 늘어날 때 색인 대상을 단계적으로 확대한다.

### 콘텐츠 작성 중 사실 오염

공식 출처가 없는 내용을 추정하거나 일반 문구로 채우면 다시 저가치 콘텐츠가 된다. 모든 변동 가능 사실에 출처와 확인일을 요구하고, 확인 불가능한 내용은 작성하지 않는다.

### 승인 후 전역 광고 회귀

루트 레이아웃에서 광고 스크립트가 발견되면 테스트가 실패하게 한다. 광고 컴포넌트는 검수 시장 경로에서 운영 설정이 켜진 경우에만 사용할 수 있도록 경계를 둔다.

### 도메인 중복

canonical만 변경하고 기존 호스트가 계속 200을 반환하면 중복 문제가 남는다. 레거시 호스트 리디렉션과 운영 환경 확인을 같은 변경의 완료 조건으로 둔다.

## 비기능 요구사항

- 새 런타임 의존성을 추가하지 않는다.
- 기존 Next.js App Router와 Vitest/Playwright 테스트 구조를 유지한다.
- 시장 원본 데이터 생성 파이프라인을 변경하지 않는다.
- 사실이 확인되지 않은 콘텐츠를 자동 생성하지 않는다.
- 광고 비활성화가 기본값이다.
- 관련 없는 UI 재설계나 지도 동작 변경을 하지 않는다.

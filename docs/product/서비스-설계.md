# 오늘장날 서비스 설계

작성일: 2026-08-29  
상태: APPROVED  
모드: Builder  
목표: 실제 공개 가능한 전국 전통시장 장날 지도 서비스

## 문제 정의

전통시장 구경을 좋아하는 사람은 특정 시장에 가기 전 장이 서는 날짜를 확인해야 한다. 그러나 장날 정보는 공공데이터, 지자체 관광 페이지, 시장 홈페이지와 블로그 등에 흩어져 있다. 시장마다 `1·6일장`, `2·7일장`처럼 규칙이 다르고 휴장, 이전, 폐장 같은 예외도 있어 검색 결과 하나만 믿기 어렵다.

첫 사용자는 시장 구경을 좋아하는 사용자의 배우자다. 핵심 상황은 “가고 싶은 시장의 다음 장날이 언제인지 알고 싶다”이며, 지도에서 주변 시장과 날짜를 함께 보며 방문지를 고르는 경험이 필요하다.

## 제품 한 문장

전국 지도에서 시장명과 다음 장날을 함께 보여주고, 시장을 선택하면 상세정보를 확인할 수 있는 전통시장 장날 지도.

## 무엇이 좋은가

- 목록을 읽지 않아도 지도에서 시장의 위치와 다음 장날을 동시에 파악한다.
- 핀에 `모란시장 · 9/4`처럼 시장명과 다음 장날이 함께 표시된다.
- 특정 날짜를 선택하면 그날 장이 서는 시장만 남아 장 구경 목적지를 발견할 수 있다.
- 각 장날에 출처와 확인일을 표시하고 잘못된 정보는 사용자가 제보할 수 있다.

## 확정한 전제

1. 처음부터 전국 시장 데이터를 공개한다.
2. 공공데이터가 실제 서비스에 충분한지 먼저 조사한 뒤 최초 데이터를 구축한다.
3. 화면의 중심은 목록이 아니라 지도다.
4. 기본 지도 핀에는 시장명과 가장 가까운 장날을 함께 표시한다.
5. 시장 핀을 선택하면 해당 시장의 상세정보 패널을 열어 다음 장날, 월간 장날, 주소, 연락처, 출처와 오류 제보 수단을 보여준다.
6. 최초 데이터 구축 이후에는 자동 동기화하지 않고 `사용자 제보 + 운영자 수동 확인·수정`으로 관리한다.

## 데이터 확보 가능성

공공데이터포털의 `전국전통시장표준데이터`는 시장명, 시장 유형, 주소, 위도·경도, 시장개설주기, 전화번호, 데이터 기준일자를 제공한다. CSV, JSON, XML 및 Open API로 받을 수 있다. 다만 이 필드와 실제 값만으로 전국 장날 서비스를 만들 수 있는지는 아직 확인되지 않았으므로 구현 전에 원본 데이터 전체를 내려받아 조사해야 한다.

- 기본 데이터: [전국전통시장표준데이터](https://www.data.go.kr/data/15012894/standard.do?recommendDataYn=Y)
- 추가 조사 대상: 정기시장 누락 여부, 장날 표기 종류, 좌표 누락·오류, 중복 시장, 폐장 시장 포함 여부
- 보조 자료: 지자체 문화관광 페이지, 시장 공식 홈페이지, 한국관광공사 대한민국 구석구석

`시장개설주기`는 문자열이므로 가져온 값을 그대로 달력에 사용할 수 없다. `매일`, `매월 1일·6일`, `2·7일장`, `매월 둘째·넷째 토요일` 등의 표현을 정규화한 뒤 실제 날짜를 계산해야 한다. 해석할 수 없는 값은 자동 게시하지 않고 검토 대상으로 분류한다.

## 고려한 접근

### A. 정적 전국 장날 달력

공공데이터를 변환해 정적 페이지를 생성하는 가장 빠른 방식이다. 운영비가 낮고 검색 노출에 유리하지만 제보 처리, 수정 이력, 관리자 검증이 어렵다.

### B. 출처가 보이는 장날 데이터베이스 — 선택

조사를 마친 전국 시장 데이터를 최초 한 번 데이터베이스에 정규화해 넣고 장날 규칙을 계산한다. 이후 데이터는 사용자 제보 또는 운영자의 수동 확인으로 수정한다. 전국 공개, 날짜 필터, 시장 상세정보와 단순한 운영 방식을 함께 지원한다.

### C. 이용자가 함께 고치는 장날 지도

사용자 편집과 상호 검증을 중심으로 운영하는 방식이다. 장기적으로 유용하지만 초기 이용자가 적을 때 검증이 작동하지 않고 허위·중복 제보를 처리할 운영 비용이 크다. MVP 이후 선택적 커뮤니티 검증 기능으로 검토한다.

## 권장 제품 구조

```text
공공데이터 원본 조사
          ↓
최초 데이터 정규화·적재
          ↓
실제 장날 날짜 계산
          ↓
시장·장날 데이터베이스
       ↙          ↘
지도 웹서비스      사용자 제보·운영자 수동 수정
```

### 구성요소

1. **웹 클라이언트**
   - 지도, 날짜 필터, 시장 검색, 상세 패널을 제공한다.
   - 데스크톱에서는 지도 오른쪽에 상세 패널을 표시한다.
   - 모바일에서는 상세 패널을 하단 시트로 표시한다.

2. **시장 API**
   - 현재 지도 영역과 날짜 조건에 맞는 시장 핀을 반환한다.
   - 개별 시장 핀에는 시장명과 다음 장날을 함께 담는다.
   - 시장별 상세 정보와 월간 장날 목록을 반환한다.
   - 핀 데이터는 가볍게 유지하고 상세 정보는 핀 선택 시 불러온다.

3. **최초 데이터 적재 도구**
   - 조사한 전국 표준데이터를 최초 한 번 데이터베이스에 넣는다.
   - 원본 값과 정규화된 값을 함께 보관해 변환 오류를 추적한다.
   - 서비스 운영 중에는 이 도구로 주기적인 자동 동기화를 하지 않는다.

4. **장날 규칙 정규화기**
   - 원문과 정규화된 규칙을 함께 저장한다.
   - 지원하는 규칙만 자동 확정한다.
   - 모호하거나 충돌하는 규칙은 `검토 필요` 상태로 보낸다.

5. **관리자 화면**
   - 사용자 제보를 확인하고 시장 정보와 장날을 수동으로 수정한다.
   - 운영자는 필요할 때 직접 변경 사항을 발견해 수정할 수 있다.
   - 수정할 때 확인 근거와 메모를 남긴다.

## 핵심 화면과 흐름

### 1. 지도 홈

- 현재 지도 영역에 있는 정기시장을 표시한다.
- 각 핀에는 시장명과 선택한 기준일 이후 가장 가까운 장날을 `모란시장 · 9/4` 형식으로 표시한다.
- 지도를 멀리 축소해 핀이 겹칠 때만 묶음 숫자로 표시하고, 개별 핀이 보이는 확대 단계에서는 시장명을 숨기지 않는다.
- 기본 날짜 범위는 `이번 주`다.
- `오늘`, `주말`, 날짜 직접 선택, `내 주변` 필터를 제공한다.
- 시장명 또는 지역 검색을 제공한다.

### 2. 시장 상세 패널

지도에서 시장 핀을 선택했을 때 열리는 해당 시장의 상세정보 영역이다.

- 시장명과 위치
- 다음 장날과 남은 일수
- 해당 월의 전체 장날 달력
- 시장 유형, 주소, 주차 정보와 연락처
- 장날 정보의 출처와 마지막 확인일
- 지도·내비게이션 길찾기 링크
- 정보 수정 제보 버튼

### 3. 오류 제보

- 로그인을 요구하지 않는 짧은 양식을 우선 사용한다.
- 스팸 방지를 위한 속도 제한과 자동 탐지 수단을 둔다.
- 제보는 즉시 공개 데이터에 반영하지 않고 관리자 검토 대기 상태로 저장한다.

## 정보 관리 방식

- 최초 적재한 정보의 출처와 데이터 기준일을 시장 상세정보에 표시한다.
- 장날은 거의 바뀌지 않는다는 전제로 주기적인 자동 수집이나 변경 감지를 운영하지 않는다.
- 사용자가 오류를 제보하면 운영자가 사실을 확인한 뒤 직접 수정한다.
- 운영자가 변경을 발견한 경우에도 관리자 화면에서 직접 수정한다.
- 제보는 확인 전까지 공개 데이터에 자동 반영하지 않는다.

## 예외와 오류 처리

- 말일이 없는 `1·6일장` 규칙은 해당 월에 존재하는 날짜만 생성한다.
- 좌표가 없거나 잘못된 시장은 주소 지오코딩 후 검토한다.
- 같은 시장이 이름만 다르게 중복된 경우 자동 병합하지 않고 후보로 제시한다.
- 지도 API 실패 시 지역·날짜 기반 목록 화면으로 대체한다.

## 배포 계획

- 사용자에게는 설치가 필요 없는 반응형 웹서비스로 제공한다.
- Git 저장소의 기본 브랜치에 병합되면 스테이징 환경을 자동 배포한다.
- 운영 배포 전 최초 데이터 적재, 장날 계산, API 및 핵심 브라우저 흐름을 자동 검증한다.
- 운영 중인 시장 데이터는 사용자 제보와 운영자의 수동 수정으로 관리한다.
- 데이터베이스 백업과 수정 이력을 보관해 잘못된 수정을 되돌릴 수 있게 한다.

지도 제공업체와 호스팅 업체는 구현 계획을 세울 때 비용, 국내 지도 품질, 사용량 제한과 이용약관을 비교해 결정한다.

## 성공 기준

1. 전국 표준데이터가 서비스에 충분한지 조사하고, 사용 가능한 모든 정기시장을 최초 데이터베이스에 재현 가능하게 적재한다.
2. 자동 정규화가 지원한 일정은 기준 사례 테스트에서 장날을 정확히 계산한다.
3. 해석할 수 없는 개설주기는 잘못된 날짜를 만들지 않고 검토 대상으로 분류된다.
4. 사용자가 시장명을 검색하거나 지도를 이동해 10초 안에 다음 장날을 찾을 수 있다.
5. 모든 시장 상세 화면에 시장명, 장날, 원본 출처와 데이터 기준일이 보인다.
6. 모바일에서 지도 핀 선택과 하단 상세 시트가 막힘없이 작동한다.
7. 오류 제보가 관리자 검토, 승인·반려와 수정 이력까지 이어진다.

## 검증 계획

- 장날 규칙 파서 단위 테스트: `1·6일장`, `매월 2일/7일`, `둘째·넷째 토요일`, `매일`, 빈 값과 비정상 값
- 날짜 계산 경계 테스트: 월말, 윤년과 연말·연초
- 최초 데이터 적재 통합 테스트: 누락, 중복과 잘못된 좌표
- API 테스트: 지도 영역, 날짜 필터, 검색과 상세 응답
- 브라우저 테스트: 지도 탐색 → 핀 선택 → 장날 확인 → 제보 제출
- 접근성 검사: 키보드로 검색과 시장 선택 가능, 핀의 시장명과 날짜를 화면 읽기 도구로 확인 가능

## 열린 결정

- 국내 지도 제공업체와 예상 월간 사용량
- 제보자가 증빙 사진을 첨부할 수 있게 할지 여부
- 공공데이터 조사 결과 부족한 시장 정보의 보완 범위
- 최초 운영자가 검토 가능한 일일 제보량과 데이터 변경량

## 다음 구현 순서

1. 전국 표준데이터 원본을 내려받아 실제 `시장개설주기` 값의 종류와 품질을 분석한다.
2. 분석 결과로 장날 규칙 문법과 검토 필요 조건을 확정한다.
3. 데이터 모델과 최초 적재·정규화 도구를 구현한다.
4. 지도 홈과 시장 상세 패널을 연결한다.
5. 출처·기준일과 오류 제보·관리자 처리를 구현한다.
6. 전국 데이터로 정확성·성능·모바일 흐름을 검증한 뒤 공개한다.

## 이번 과제

아내분에게 목업을 보여준 뒤 설명하지 말고, “가고 싶은 시장의 다음 장날을 찾아봐”라고 부탁한다. 첫 클릭, 막힌 지점, 기대했지만 없었던 정보 세 가지만 기록한다. 이 관찰 결과를 구현 전에 화면 우선순위에 반영한다.

## 이번 대화에서 확인한 점

- “대부분 시장가는 사람들은 사실 장날 구경하러 가는 게 더 크다”는 관찰이 서비스의 중심을 일반 시장 안내에서 장날 탐색으로 바꿨다.
- 초기 목업이 검색·달력 중심이었을 때 “기대한 건 지도에 표기되는 것”이라고 바로 수정했다. 따라서 지도는 부가 기능이 아니라 첫 화면이다.
- 전국 공개 전에 공공데이터가 충분한지 조사하고, 최초 적재 이후에는 사용자 제보와 운영자 수동 수정으로 관리하기로 했다.

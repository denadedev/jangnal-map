# 외국인 대상 첫 출시 CEO 계획 리뷰

- 2026-09-28
- 대상: `docs/product/2026-09-28-english-traveler-plan.md`, `docs/superpowers/plans/2026-09-28-english-search-landing.md`
- 리뷰 방식: HOLD SCOPE. 사용자가 선택한 C안(영어 시·도 검색·한국 날짜 기준)을 검토한다. 사용자가 추가로 제안한 지도 서비스 선택은 별도 제품 결정으로 반영했다.
- 결론: **조건부 진행**. 외국인 방문자가 실제로 지역과 날짜를 찾아갈 수 있는 방향이다. 최신 main과의 차이, 영어 검색의 한계, 날짜·필터 의미를 구현 검증에서 반드시 해결해야 한다. 코드와 배포는 변경하지 않았다.

## 제품 판단

현재 계획의 강점은 한국 여행자가 필요한 두 입력, 지역과 방문 날짜를 중심에 둔 것이다. 해외 IP 방문 비율만으로 외국인 수요를 증명하지는 못한다. 검색 결과 노출은 발견의 지표이고, 사용자가 시장을 선택하고 지도 앱을 열 수 있는지는 별개의 검증 과제다.

영어 관광 정보는 이미 한국관광공사에서 제공한다. 오늘장날의 차별점은 일반 시장 소개보다 **여행 날짜에 맞는 장날을 지도에서 고르는 기능**이다. 안내 페이지도 이 기능을 첫 문장에서 설명해야 한다.

```
현재: 한국어 지도 + 한글 이름/주소 + 기기 날짜
  → 첫 출시: 영어 안내/핵심 UI + 영어 시·도 검색 + 한국 날짜 + 지도 앱 선택
  → 12개월 목표: 검수된 영문 시장명/검색 + 신뢰도 높은 방문 날짜 + 현지 이동 지원
```

### 검토한 구현 방식

| 방식 | 장점 | 한계 | 결정 |
| --- | --- | --- | --- |
| 영어 소개 한 장 | 가장 작은 변경 | 한국어 지도에서 외국인이 막힌다 | 기각 |
| 영어 UI만 번역 | 화면 조작은 가능 | 영어 지역 검색과 한국 날짜가 빠진다 | 기각 |
| 날짜·지역을 찾는 영어 탐색 | 실제 여행 과업까지 검증 가능 | UI 번역 대상과 테스트가 늘어난다 | 사용자 선택 |

### 범위 밖

- 1,393개 시장의 영문명·주소·소개 생성: 공식 명칭과 데이터 품질 검수가 선행되어야 한다.
- 영문 독립 상세 페이지: 이번에는 영어 지도 상세 시트로 과업을 완료한다.
- Google의 한국 내 도보·차량 경로 보장: 확인된 지원 범위를 넘는 약속이다.
- 자동 번역·언어 감지·영어 제보 폼: 현재 여행 과업에 필수는 아니다.
- 새 지도 SDK·서버 API: 기존 시장 좌표와 외부 지도 링크를 재사용한다.

### 이미 있는 것

- 1,393개 시장과 일정 유형: `apps/web/public/data/markets.json`.
- 일정 계산: `apps/web/src/lib/schedule.ts`, 필터/검색: `apps/web/src/lib/market-view.ts`.
- 지도 실패 시 목록 대체와 시장 상세: `MarketExplorer`, `MarketMap`, `MarketList`, `MarketDetail`.
- Umami의 페이지 방문 집계와 영어 경로를 넣을 sitemap: `app/layout.tsx`, `app/sitemap.ts`.
- NAVER 좌표 경로: `MarketDetail`과 독립 시장 상세 페이지.

## 1. 구조

```
Google 검색 → GET /en → 영어 본문·안내 → /en/map
                                        ├─ 번역 문구(locale=en)
                                        ├─ 시장 JSON → 시·도 별칭 매칭 → 날짜 필터(KST 달력일)
                                        ├─ NAVER 지도 / 실패 시 목록
                                        └─ 시장 선택 → 상세 → 지도·길찾기 한 버튼
                                                               ├─ NAVER: 경로
                                                               └─ Google: 좌표 위치
한국어 / → 같은 시장 원본·일정 함수, 기존 한국어 경로 유지
```

핵심 결합점은 `MarketExplorer`의 하드코딩된 `/` 주소 갱신과 시장 공유 링크다. 영어 URL을 잃지 않도록 locale별 경로 함수 한 곳에서 구성한다. 일정 계산에는 한국 달력일을 전달한다. 원본 데이터를 중복 복사하지 않는다.

**P1 발견:** 작업 트리 HEAD `87fdcf0`은 최신 `origin/main`보다 한 커밋 뒤다. 최신 커밋 `39b27f7`이 모바일 첫 화면·시장 미리보기·키보드 대응을 크게 바꿨다. 현재 파일만 기준으로 구현하면 영어 모바일 요소를 빠뜨린다. 구현 시작 시 최신 main으로 작업 트리를 맞추고 컴포넌트 경계를 재확인한다. 이 단계는 계획 Task 0에 반영했다.

**P2 남은 설계 부채:** 공통 루트의 `<html lang="ko">`는 영어 화면과 맞지 않는다. 초기 출시에서 영어 콘텐츠 영역에 `lang="en"`을 지정해 본문 읽기를 보완한다. 완전한 문서 언어 분리는 라우트 그룹의 별도 루트 레이아웃이 필요하므로 이번 범위에 억지로 섞지 않는다. 영어 문서 제목까지 화면 읽기 도구로 확인한다.

서버 새 쓰기·데이터베이스·새 API는 없다. 10배/100배 방문에서 새 병목보다 기존 1,393개 시장 렌더링·지도 SDK가 먼저 한계가 된다. 새 경로의 정적 안내와 작은 지역 별칭 표는 부하가 작다.

## 2. 오류와 복구

| 경로 | 실패·오류 유형 | 현재/계획된 복구 | 사용자에게 보이는 것 |
| --- | --- | --- | --- |
| 시장 JSON fetch | HTTP 오류 `Error`, JSON 구문 `SyntaxError`, 배열 형식 `Error` | React Query 오류 상태, 다시 시도 | 영어 오류·재시도 |
| NAVER SDK | 로딩/시간 초과 `Error` | 기존 목록 대체 | 영어 목록 안내 |
| 위치 권한 | `GeolocationPositionError` 거부/시간 초과 | 위치 정렬 해제, 검색 안내 | 영어 오류·지역 검색 |
| 영어 시·도 별칭 | 일치 없음, 빈 입력 | 한글 원문 검색 또는 전체 결과/빈 상태 | 영어 범위 설명·조건 초기화 |
| URL `market` ID | 존재하지 않음/필터 결과 밖 | 선택 해제, 목록 유지 | 결과 목록 |
| 공유 | Clipboard `DOMException` 또는 취소 | 기존 오류 피드백, 취소는 오류 취급하지 않음 | 영어 복사 실패 안내 |
| Google 링크 | 좌표 없음/외부 서비스의 경로 미지원 | 좌표 없으면 링크 숨김; Google은 위치 보기로만 안내, NAVER 경로 선택 가능 | 과장 없는 선택 항목 |
| KST 날짜 변환 | 잘못된 직접 날짜, 날짜 경계 | 기존 정규화와 달력 날짜 계약 유지 | 유효한 날짜 또는 기준일 |

**확인할 오류 누락:** 현재 지도 SDK 실패 시 목록은 보이지만, 최신 모바일 미리보기 상태에서도 영어 오류 안내가 목록을 가리지 않는지 실기기 크기로 검증해야 한다. 외부 지도에서 경로를 제공하지 않는 상황은 앱이 검출할 수 없으므로 Google을 ‘위치 보기’로 표기한다.

## 3. 보안

새 인증·결제·서버 입력·비밀키는 없다. 새 입력은 기존 검색 문자열과 URL 쿼리이며 고정된 시·도 별칭과 비교한다. 외부 지도 링크는 고정된 NAVER/Google 호스트와 검증된 시장 좌표로만 만든다. `query`, `market` 등을 목적지 URL의 호스트로 쓰지 않는다. 기존 지도 마커의 HTML 이스케이프를 유지한다. 악성 URL 문자열·긴 검색어·없는 시장 ID로 스크립트 실행이나 외부 도메인 이동이 발생하지 않아야 한다. 위험도: 낮음, 사용자 신뢰에 미치는 영향은 중간.

## 4. 데이터와 화면 상호작용

```
입력(영문 지역/한글 시장, 날짜, 시장 ID)
  → 검증(17개 지역 표기, YYYY-MM-DD, 유효 시장 ID)
  → 변환(영문 시·도→원본 한글; 현재 시각→KST 달력일)
  → 필터(기존 일정 함수, 원본 JSON)
  → 결과(지도/목록/상세/공유 URL)
     ├─ 입력 없음: 기본 지역 전체와 기본 날짜 필터
     ├─ 결과 없음: 영어 빈 상태, 초기화
     ├─ JSON 오류: 영어 재시도
     └─ 좌표 없음: 목록·주소는 유지, 지도 앱 메뉴 숨김
```

**P1 발견:** 기존 Today/Week/Weekend 필터는 상설시장 일부를 제외한다. 영어에서 ‘open today’라고 쓰면 사실과 달라진다. 계획에 `Market days today`처럼 정기 장날 중심 결과임을 밝히고 `All markets`에서 상설시장을 볼 수 있게 설명했다. 포함 로직은 이번 범위에서 바꾸지 않는다.

**사용자 후속 보완:** 상설시장과 장날을 양자택일로 설명하면 데이터와 맞지 않는다. 현재 공개 데이터에는 `marketType=상설장`과 `schedule.kind=digit-pair`가 함께 있는 항목이 153곳 있다. 영어 안내에는 상설 점포와 정기 장날이 같은 시장에 공존할 수 있고, 어느 표시도 모든 점포의 실시간 영업을 보장하지 않는다고 적는다. 구현 계획과 검증 항목을 함께 수정했다.

**방문 동기 보완:** 사용자는 장날에 판매 물품과 볼거리가 평소보다 훨씬 많다는 차이를 강조해 달라고 했다. 한국관광공사의 [예산시장 안내](https://english.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=191378)는 5일장에 시장 규모와 활기가 커진다고 설명하고, [안동 중앙신시장 안내](https://english.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=177574)는 판매자가 늘어난다고 설명한다. 따라서 영어 안내의 앞부분에 장날을 선택할 이유를 구체적으로 적되, 모든 시장의 물품 수나 행사까지 보장하는 문장은 피한다.

지역 매핑은 영문 공백·대소문자와 자주 쓰는 표기를 정규화한 뒤 17개 시·도에 한정한다. 원본 전북 주소에는 `전북특별차치도` 오기가 있어 이 값을 실제 데이터로 테스트한다. 부분 영어 시장명 검색은 지원한다고 약속하지 않는다.

지도 앱 선택은 한 버튼에서 펼치는 목록이다. 빠른 연속 클릭·Escape·시장 변경·외부 새 탭 이동·모바일 시트 닫기에서 목록과 포커스가 정상 상태로 돌아와야 한다. 지도 SDK 실패 후 목록에서 시장을 고르는 흐름도 같은 메뉴를 제공한다.

## 5. 코드 품질

`Locale`과 문구 사전은 화면 문구의 공유 경계다. 지역 표기 매핑은 일정 함수와 분리한다. KST 날짜 변환은 현재 시각에서 달력 연·월·일을 한 번만 뽑고, 기존 일정 함수의 로컬 달력 Date에 전달한다. 그 값을 다시 시간대 변환하면 하루가 중복 이동할 수 있다. URL 경로 구성·공유 링크를 컴포넌트 곳곳에 복제하지 않는다. 제공자 메뉴는 상세 시트와 한국어 독립 상세 페이지가 공유한다. 번역을 위해 새 패키지나 전역 상태 서비스를 도입하지 않는다.

## 6. 테스트

```
새 UX: /en 안내 → /en/map → 영문 지역 → 날짜 → 시장 선택 → 지도 앱 선택
새 데이터: 영문 별칭 → 한글 시·도; 현재 UTC 시각 → KST 달력일
새 코드 경로: ko/en 문구, 두 지도 URL, 좌표 없음, 영어 공유 URL
새 비동기: 기존 시장 fetch·NAVER SDK·위치 권한·클립보드
새 백그라운드 작업: 없음
```

핵심 단위 테스트는 17개 지역 별칭(전북 오기 포함), KST 자정·월말·연말·윤년, `getMapPath`와 공유 URL, Google 좌표 URL 인코딩이다. 브라우저 테스트는 영어 홈의 서버 HTML·메타데이터, 지도 데이터 실패, 모바일 preview/detail·뒤로 가기, 키보드로 지도 앱 메뉴 선택, 한국어 회귀를 다룬다. 외부 NAVER/Google 서비스 자체를 자동 테스트하지 않는다. 수동으로 iOS·Android에서 위치 좌표와 Google의 실제 표시를 확인한다. 시간 의존 테스트는 고정 시각을 주입해 재현 가능하게 한다.

출시 판단을 위해 영어 사용자 3명에게 ‘Seoul과 특정 여행 날짜로 시장을 찾아 지도 앱을 열기’를 설명 없이 맡기는 짧은 관찰을 권한다. 2명도 완료하지 못하면 문구·검색·선택 흐름을 수정한다. 적은 표본으로 수요 자체를 결론 내리지 않는다.

## 7. 성능

새 서버 요청이나 DB 조회는 없다. 지역 별칭 17개는 기존 1,393개 시장 필터의 문자열 검사와 함께 처리한다. 새 정적 영어 안내는 지도 SDK를 로드하지 않는다. Google 외부 링크는 클릭 전 네트워크 요청을 발생시키지 않는다. 느린 순서는 기존 지도 SDK, 시장 JSON, 다수 마커 갱신이며 기존 클러스터링과 fallback을 유지한다. 성능 수치는 측정 전 추정하지 않는다. 모바일 느린 네트워크에서 지도 실패 후 목록 사용이 가능한지 확인한다.

## 8. 측정과 디버깅

Search Console의 `/en` 색인·검색어·노출·클릭과 Umami의 `/en`, `/en/map` 방문을 본다. Direct는 출처 미확인이며 외국인 또는 검색 유입으로 해석하지 않는다. 현재 계획에는 지도 앱 선택 이벤트가 없어 NAVER와 Google 사용량은 구분할 수 없다. 이는 출시 후 확장 판단의 관측 한계로 명시한다. 실제 과업 성공은 3명 관찰로 보완한다. 오류가 나면 경로, 언어, 날짜, 시장 ID, 지도 SDK/JSON 상태를 재현 정보로 기록하되 검색어 원문이나 위치 좌표를 분석 서비스에 새로 보내지 않는다.

## 9. 배포와 되돌리기

DB 마이그레이션과 비밀키 변경은 없다. 구현은 최신 main의 모바일 UI를 기반으로 한다. 스테이징 또는 로컬 프로덕션 빌드에서 `/`, `/en`, `/en/map`, sitemap, 모바일 메뉴와 상세를 검사한 뒤 기존 CI/K3s 배포 흐름으로 반영한다. 새 Pod와 이전 Pod가 잠깐 섞일 때 새 `/en/map` 링크가 구버전 Pod에서 404가 될 수 있으므로 배포 직후 경로를 확인한다. 문제 시 이전 이미지/커밋으로 GitOps 롤백하고 `/` 한국어 지도 정상 동작을 우선 확인한다. 배포 자체는 이번 리뷰 범위가 아니다.

## 10. 장기 방향

이번 변경은 향후 영문 시장명·주소를 추가할 수 있는 locale·별칭 경계를 남긴다. 가장 큰 부채는 영어 문서의 루트 `html lang`이 한국어인 점과 시장 고유명사의 한글 유지다. 첫 버전에서 영역별 `lang`과 영어 입력 범위 설명으로 완화하고, 영어 독립 상세를 만들 때 라우트 그룹 분리를 검토한다. 설계는 되돌리기 4/5: DB·API 변경이 없지만 여러 UI 컴포넌트에 locale props가 퍼진다. 6개월 후 문구 사전의 키·링크 경로를 찾기 쉽게 README에 기록한다.

## 11. 디자인과 사용성

```
영어 검색 결과
  → 영어 안내(날짜·지역 가치, 5일장 설명)
  → 영어 지도(지역 검색·날짜 필터)
  → 결과(목록/지도, 실패 시 목록)
  → 시장 상세(한글 고유명사 + 영어 일정·정보 라벨)
  → 지도·길찾기 한 버튼(제공자 선택) → 위치/경로 확인
```

첫 화면에서 길게 서비스 철학을 설명하지 않고 날짜와 지역을 바로 선택하게 한다. 한글 고유명사가 남는 점은 시작 전에 알려 신뢰를 지킨다. 모바일 320·375·430px에서 긴 영어 필터·지도 앱 선택 목록·시트 높이를 확인한다. 키보드 포커스, `aria-expanded`, Escape, 한글 이름의 `lang="ko"`를 검증한다. 새 모달 위에 기존 모바일 시트를 또 올리지 않는다. 기본적인 색·타이포그래피는 기존 화면을 따른다.

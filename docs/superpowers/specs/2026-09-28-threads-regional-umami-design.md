# Threads 권역별 게시와 유입 측정 설계

상태: 승인된 대화 방향을 반영한 구현 기준. A/B 실험은 하지 않는다.

## 목표

오늘·내일 장날인 5일장 세 곳을 매 게시물마다 **하나의 광역권**에서 소개한다. 본문은 확인된 시장 데이터만 사용한다. 답글은 설명 한 줄과 클릭 가능한 링크 카드로 구성하고, URL 문자열은 답글 문장에 넣지 않는다. 카드의 연결 주소에는 게시물별 UTM 코드를 넣어, 사용자가 수동 기록하는 Threads 조회수와 Umami의 사이트 도착 수를 비교할 수 있게 한다.

광역권은 **게시물의 시장 선정·소개 문구에만** 적용한다. 사이트에 별도 광역권 필터를 만들거나 링크에 지역 검색어를 넣지 않는다.

## 게시물

- 기존 스케줄(매일 08:30, 월~토 20:30 한국 시간), 계정 확인, 초안 저장, 중복·만료 차단, 게시 단계와 오류 알림을 유지한다. 워크플로 수동 실행은 실제 게시로 이어질 수 있으므로 검증에 사용하지 않는다.
- `markets.json`에서 대상 날짜에 운영하는 `digit-pair` 시장을 선택한다. 운영 상태, 주소, 광역권 표기, 30일 시장 중복을 확인한다. 광역권에 후보가 3개 이상인 곳만 허용하고, 최근 소개한 권역은 가능하면 피한다. 선택 가능한 권역이 없으면 이유를 알리고 게시를 건너뛴다. 일일 상설시장을 5일장으로 소개하지 않는다.
- 도입·질문은 기존 안전한 후보 표현을 사용하고 시장명·날짜·지역·전체 집계는 코드가 조립한다. `오늘/내일 [광역권] 장날인 시장 세 곳`을 명시하고, 세 시장이 정확히 같은 광역권·대상 날짜인지 검증한다. 300자 제한과 동일 본문 차단을 유지한다.
- 원본 데이터에서 `전북특별차치도`처럼 잘못된 광역권 표기는 정상 표기로 교정하거나 선정 대상에서 제외한다. 사실과 다른 지역명은 게시하지 않는다.

## 링크 카드와 방문 이벤트

예: `https://kmarketday.com/?when=date&date=2026-09-29&utm_source=threads&utm_campaign=202609282030`. 코드는 한국 시간 **게시 날짜와 슬롯**에서 파생하므로 한 슬롯에 한 주소다. 본문이나 답글 문장에는 이 URL을 쓰지 않는다. n8n의 `link_attachment`에만 넣고, 답글 텍스트에는 `내일 운영하는 전통시장 전체 보기 👇`처럼 짧은 안내만 둔다. 링크가 열리면 해당 날짜의 전체 시장 목록을 보여준다. 카드에는 사이트 이름이나 도메인이 표시될 수 있다. A/B 전용 경로나 별도 단축 URL은 만들지 않는다.

사이트는 첫 URL을 읽을 때 주소가 `replaceState`로 정리되기 전에 `utm_source=threads`와 형식이 맞는 `utm_campaign`만 캡처한다. 캠페인 날짜·슬롯과 탐색 날짜가 서로 맞아야 한다. 빈 값, 다른 출처, 중복 UTM, 임의 문자열은 무시하되 사이트 탐색은 정상 작동한다. Umami 기본 페이지뷰의 `data-exclude-search="true"`는 유지하고, 유효한 캠페인 코드만 `threads_entry` 사용자 이벤트의 데이터로 전송한다. 개인 식별자·검색어·전체 URL은 이벤트에 넣지 않는다. 분석 스크립트가 차단되거나 늦게 로드되면 시장 탐색을 막지 않고 방문 집계만 빠질 수 있다.

기존 일반 주소와 과거 Threads 링크는 계속 작동한다. 날짜가 지난 유효한 링크는 사이트의 현재 날짜 처리 규칙을 따른다. 카드 미리보기에는 기존 홈페이지의 Open Graph 제목·설명이 적용된다. 실제 카드의 외형과 도메인 표시는 Threads 쪽 렌더링에 따라 다를 수 있다.

## 확인할 성과

사용자는 게시물 조회수를 수동 기록한다. Umami에서 캠페인 코드별 `threads_entry` 이벤트를 조회해 `사이트 도착 수 ÷ 본문 조회수 × 1,000`을 본다. 이는 광고의 고유 클릭 수나 실제 시장 방문 수가 아니다. 새로고침 중복, 분석 차단과 링크 미리보기 등으로 차이가 날 수 있으므로 절대 수치보다 추세와 게시 유형을 본다.

## 적용 순서와 실패 대응

1. 사이트 코드와 테스트를 먼저 준비하고 배포한다. 실제 게시에 쓰지 않는 QA 코드로 브라우저 한 번 방문이 이벤트 한 번으로 기록되는지, 일반 주소·잘못된 UTM·분석 차단에서 탐색이 유지되는지 확인한다.
2. 사이트 수집을 확인한 뒤 n8n의 권역 선택·본문 검증·답글 카드 주소를 함께 변경한다. 새 주소 규칙과 코드의 날짜·슬롯을 게시 전 검증한다. 실제 Threads 게시를 수동 실행하지 않는다.
3. 저장된 활성 워크플로를 다시 조회한다. 첫 예약 초안의 권역·시장·날짜·카드 주소를 사람이 확인하고, 첫 자동 게시의 본문·카드·Umami 이벤트를 확인한다.
4. 새 게시물에 잘못된 사실이나 링크 오류가 있으면 이전 n8n 버전으로 되돌린다. 이미 게시된 카드 링크가 계속 열리도록 사이트의 캠페인 URL 처리는 남겨 둔다.

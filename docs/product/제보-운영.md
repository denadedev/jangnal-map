# 사용자 제보 운영 절차

## 접수 채널

- 모든 제보는 오늘장날 `/report` 화면에서 받는다.
- `/api/report`는 Nodemailer와 Gmail SMTP로 전용 운영 이메일 한 곳에 전달한다.
- 제보를 별도 데이터베이스에 저장하지 않는다.
- 발송에는 개인 주계정이 아닌 전용 Google 계정과 앱 비밀번호를 사용한다.
- 공개 API에는 입력 검증, 본문 크기 제한, 동일 출처 검사와 honeypot을 적용한다.
- 공개 전에 Vercel Firewall에서 `POST /api/report`에 IP당 10분 5건의 고정 구간 요청 제한을 게시하고 초과 요청은 429로 응답한다.
- 제한을 우회한 스팸이 반복되면 CAPTCHA를 추가한다.

## 메일 상태

- 신규: 아직 확인하지 않은 제보
- 확인 중: 공식 출처나 지자체 확인을 시작한 제보
- 완료: 공개 데이터 반영 또는 안내 회신을 마친 제보
- 반려: 근거 부족, 중복 또는 사실과 다른 제보

## 처리 순서

1. 장날, 휴장·폐장, 위치 오류를 먼저 처리한다.
2. 시장 공식 채널, 지자체 또는 신뢰 가능한 공개 출처로 확인한다.
3. 확인 근거 URL과 판단 메모를 데이터 보정 기록에 남긴다.
4. 공개 JSON을 다시 생성하고 전체 테스트와 빌드를 실행한다.
5. 사용자의 배포 승인을 받은 뒤 Vercel에 반영한다.
6. 연락처가 있으면 결과를 회신하고 메일을 완료로 이동한다.

## 개인정보와 자격증명

- 연락처는 답변 목적으로만 사용한다.
- 공개 데이터와 변경 근거에는 연락처를 복사하지 않는다.
- 처리 완료 이메일은 90일 이내 삭제한다.
- 삭제 요청은 `REPORT_TO_EMAIL`에서 이전 제보의 연락처와 내용을 받아 대조한 뒤 처리한다.
- `SMTP_PASS`는 Vercel 환경 변수에만 저장하고 저장소, 로그와 채팅에 남기지 않는다.
- 앱 비밀번호가 노출되면 즉시 폐기하고 새로 발급한다.

## 주간 확인

- 전체 접수 수
- 유효 제보 수
- 신규와 확인 중 제보 수
- 가장 오래 대기한 제보의 일수
- 스팸 수

## 자체 시스템 전환

- 유효 제보가 주 5건을 4주 연속 초과
- 미처리 제보가 20건 이상 누적
- 두 번째 운영자 추가
- 메일 분류만으로 제보 처리 이력을 추적하기 어려움
